| 9 | Созданы ли замкнутые контуры для подсистем, работающих с ПДн и финансовыми данными (отдельные сети/кластеры, изолированные БД)? | | Снижает риск распространения инцидента на остальные системы. |
| 10 | Ограничен ли доступ к системам из внешних источников (только через API Gateway, WAF, с валидацией токенов)? | | Партнёрские API и интеграции с госорганами должны проходить через контролируемый периметр. |

| 12 | Используются ли средства управления учётными записями на базе единого реестра (автоматическая синхронизация прав)? | | Важно для гибридной инфраструктуры (ЦОД + облако). |

| **II. Безопасность данных** | | | |
| 1 | Разработана и актуализирована ли политика классификации данных в соответствии с ФЗ‑152 и ISO/IEC 27001? | | Должна покрывать ПДн, финансовые данные, секреты, публичные данные. |
| 2 | Используется ли шифрование данных при хранении (TDE/AES) и передаче (TLS 1.3) во всех доменах? | | Особое внимание — БД CRM, БД сделок, хранилища персональных данных. |
| 3 | Реализованы ли механизмы управления ключами шифрования (ротация, HSM, разделение ролей)? | | HSM нужен для ключей шифрования БД и сертификатов для онлайн‑сделок. |
| 4 | Проводится ли регулярное резервное копирование данных (в т. ч. журналов аудита)? Хранятся ли копии в защищённых хранилищах? | | Глубина хранения должна соответствовать требованиям законодательства и бизнес‑потребностям. |
| 5 | Выполняется ли ежемесячное тестирование восстановления данных из резервных копий? | | Без тестов нельзя гарантировать, что бэкапы пригодны для восстановления. |
| 6 | Ограничен ли доступ к резервным копиям, и зашифрованы ли они? | | Риск: злоумышленник может украсть бэкап и получить все данные. |
| 7 | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки для разных типов данных? | | Нужно для соответствия ФЗ‑152: маркировка, сроки хранения, право на удаление. |
| 8 | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности? | | Метки позволяют автоматически блокировать доступ к конфиденциальным данным при подозрительных действиях. |
| 9 | Разработаны ли процессы Data Governance (владельцы данных, правила качества, регламенты обмена)? | | Решает проблему несистемного контроля потоков данных между доменами. |
| 10 | Реализованы ли процессы безопасного уничтожения данных (при отзыве согласия, истечении срока хранения)? | | Обязательно для ПДн в соответствии с ФЗ‑152. |
| 11 | Используются ли механизмы контроля целостности данных (хэши, цифровые подписи, контрольные суммы)? | | Критично для юридически значимых данных (договоры, статусы сделок). |
| 12 | Реализованы ли процессы контроля сохранности данных (проверка на удаление/изменение, аудит изменений)? | | Помогает выявить несанкционированные правки (например, подмену данных клиента). |
| 13 | Применяются ли процессы анонимизации/псевдонимизации данных для тестовых сред и аналитики? | | Снижает риски при использовании данных в BI/ML и тестировании. |
| 14 | Разработана ли инструкция по процессу восстановления данных с указанием ролей, сроков и ответственных? | | Нужна для быстрого восстановления после инцидентов. |
| **III. Защита инфраструктуры** | | | |
| 1 | Используется ли межсетевой экран для ограничения входящего и исходящего трафика (в ЦОД и облаке)? | | Правила должны быть явно разрешёнными, всё остальное — запрещено. |

| 3 | Используются ли IDS/IPS‑системы для обнаружения и предотвращения сетевых атак? | | Важно для защиты периметра и выявления сканирования портов, попыток подбора паролей. |
| 4 | Настроен ли мониторинг сетевого трафика на аномалии и DDoS‑атаки? | | Особенно критично для публичных сервисов (онлайн‑витрина, онлайн‑тур). |
| 5 | Проводится ли еженедельное сканирование уязвимостей ОС, приложений и сетевых устройств? | | Помогает выявлять незакрытые уязвимости до того, как ими воспользуются злоумышленники. |
| 6 | Установлены ли на серверах и рабочих станциях антивирусы и системы EDR? | | EDR позволяет детектировать сложные атаки и реагировать на них. |
| 7 | Отключены ли неиспользуемые службы и порты на серверах, рабочих станциях и сетевом оборудовании? | | Уменьшает поверхность атаки. |
| 8 | Используются ли механизмы контроля целостности системных файлов? Ведётся ли журналирование доступа к системным ресурсам? | | Позволяет выявить компрометацию ОС и несанкционированные изменения. |
| 9 | Проводятся ли автоматизированные сканирования облачных инфраструктур на соответствие рекомендациям безопасности? | | В гибридной среде легко допустить небезопасные конфигурации (открытые S3‑бакет, публичные БД). |
| 10 | Реализовано ли автоматическое обновление сигнатур защиты от вредоносных программ? | | Обеспечивает защиту от новых угроз. |
| 11 | Осуществляется ли фильтрация трафика между сетевыми сегментами (в т. ч. между доменами продаж, ЖКУ, финансов)? | | Предотвращает несанкционированный доступ между доменами. |
| 12 | Используются ли средства для контроля периметра доступа (WAF, API Gateway)? | | WAF защищает веб‑приложения от OWASP Top 10, включая XSS и SQLi. |
